# Choose my places

The day planner now offers **Choose my places** alongside automatic planning. Set a destination, source, date, available hours and preferences, then open the separate page. No location is selected automatically.

Click a category to load a real Google Places shortlist for the selected destination and nearby area. Results include the provider address, available photo/attribution, rating, suggested visit allowance and known admission range. The current discovery endpoint returns up to eight eligible results per category; this is not an exhaustive directory. Refresh explicitly for updated evidence, or use **Search another place**, select a real autocomplete suggestion and press **Add searched place**. Plain typed text cannot be added. Nearby places can lie outside city administrative boundaries; addresses and itinerary warnings identify these. Visits must remain in the destination country.

Add up to five distinct visits, edit each duration (10–240 minutes), remove visits, and choose whether to include the existing conditional midday meal. Category switches preserve chosen visits; switching destination or date clears them. Other preference changes invalidate the route and category cache. Chosen visits stay in memory while navigating within the app and are not saved on refresh before acceptance.

**Optimize route** is the only planning trigger on this page. It submits verified candidate IDs/receipts, `chosenPlaces: true`, smart ordering, AI selection disabled and every chosen visit marked `mustVisit`. The backend validates these conditions and compares feasible permutations with the existing least-travel objective. It preserves user durations and applies Google travel times, opening windows, the budget evidence, buffers, breaks, meal-detour checks, party/food/accessibility preferences and the original return destination. It never adds another attraction or silently removes a chosen visit. An infeasible route returns an actionable error. Traffic estimates and unknown venue costs remain estimates, not a guaranteed globally shortest route or complete price quote.

The optimized preview includes the whole journey map, existing compact itinerary and budget review. A review acknowledgement and **Accept my chosen itinerary** are required before saving. Acceptance uses the existing local trip library, price summary, sharing and progress flows. Previous accepted trips survive browsing, edits and failures. Changing inputs or navigating away cancels pending requests; request sequences suppress stale results and duplicate requests.

Categories are browsing filters for this explicitly selected itinerary, rather than automatic-planner interest requirements. Other trip preferences remain applied. This path uses Google Places/Geocoding/Routes and existing credentials; it does not call Gemini or require another API key. Existing provider allowances and endpoint rate limits remain in force.

Validation: `tests/e2e/choose-places.spec.ts` covers browsing, explicit planning, required selections, user durations, meals, separate returns, acceptance-only saving/reload, provider failures, invalid selections, stale requests and mobile layout. `tests/guide.test.ts` checks minimum-travel permutation selection, preservation of all required visits, request validation, Gemini bypass and infeasible routes.
